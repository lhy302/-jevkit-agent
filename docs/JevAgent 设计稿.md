## 0. 最终统一口径（最高优先级）

以下为最高优先级解释，后续条款均围绕其展开：

> **路由表 schema 冻结；`/dynamic` 是独立运行期层；动态节点结构封闭、实例动态；词表工厂仅任务前生效；公约数层独立为 `semantic_v1`；特化映射静态优先；回滚按确认点版本向量；可逆按执行动作判定；词表语法 Jev 审、词条语义通用 Agent 审；异构要求不同类型模型；规则沉淀分散在各表；DSL 双格式，S-表达式 canonical；三层 DSL 中通用 Agent 写公约数 DSL，Jev 验证与规范化；特化层是一等公民；raw 是安全阀。**

补充口径：

- 通用 Agent 负责逻辑分解、公约数 DSL 编写、全局状态、符号表、接口契约、风格统一、质疑处理、词表工厂。
- JevAgent 负责块内路由、节点存在性检查、描述规范化、特化映射选择、符号选择、模板填充、词表语法验证、结构化质疑。
- 审查层负责 Tier 1 确定性检查、Tier 2 异构通用 Agent 交叉审查、Tier 3 人类仲裁。
- 人类只处理分歧，不处理流程；工作量 O(分歧数)，非 O(任务量)。

## 1. 系统定位

JevAgent 不是通用 Agent，也不是代码生成器。它是一个**受约束的逻辑落地执行器**：

- **输入**：一段逻辑描述 / 已写好的公约数 DSL + 一张目标语言路由表 + 当前符号环境 + 词表。
- **输出**：确定性代码 / 命令 / DSL 文本。
- **不负责**：理解长逻辑、管理全局状态、编排任务顺序、生成公约数 DSL。

它的核心价值在于：**在封闭集合内做精确判断，把幻觉从代码层消除**。

在跨语言分层语义架构下，JevAgent 的职责进一步收缩为：

- 在公约数层：检查节点存在性、规范化描述、分流幻觉与偏差。
- 在特化层：从语言特化子树中选择叶子、填充模板、做语法补全选择。
- 在词表工厂：验证候选词表的语法正确性，不做词条语义创造。

## 2. 核心概念

| 概念 | 说明 |
|------|------|
| **Jev** | 只做 Choice / Score / Noul 三类判断的模型，不生成自由文本。 |
| **路由表** | 树形结构，描述从抽象逻辑到目标语言语法的映射路径。 |
| **词表** | 封闭集合，任务前可扩展，任务期间不可新增。 |
| **模板表** | 封闭集合，定义叶子节点的代码形态与槽位。 |
| **对话表** | 封闭集合，把结构化缺口翻译成人话。 |
| **逻辑 DSL** | 语言无关的高层逻辑文本表示，可读、可编辑、可回写。 |
| **公约数语义层** | 独立路由表 `semantic_v1`，只保留跨语言可验证行为等价的抽象节点。 |
| **语言特化层** | 各目标语言表的特化子树，处理指针、内存、并发、语法糖等语言特有细节。 |
| **三层 DSL** | 逻辑描述 → 公约数语义层 → 语言特化层 → 目标代码。 |
| **块** | 通用 Agent 切分出的独立逻辑单元，是 Jev 的处理粒度。 |
| **确认点** | 通过审查的块，是回滚锚点。 |
| **确认点版本向量** | 绑定代码、DSL、符号表快照、动态节点、契约、表版本、缓存键等状态。 |
| **词表工厂** | 通用 Agent 为特定任务生成候选词表，Jev 验证语法正确性。 |
| **动态符号表** | 运行期维护的变量、函数、模块、类、别名等符号集合。 |
| **`/dynamic` 层** | 独立运行期层，不是目标语言表的静态节点，也不是表扩展。 |
| **manifest** | 统一版本绑定文件，包含 skeleton、semantic、table、vocab、mapping、symbol_snapshot、code_commit、dsl_commit。 |
| **raw 节点** | 不可提取部分的显式保留，作为特化层安全阀，不参与公约数层等价性验证。 |

### 3.2 三层 DSL 架构

```
逻辑描述（自然语言 / 高层需求）
    ↓ 通用 Agent（语义理解、逻辑分解、编写 DSL）
公约数语义层（语言无关 DSL）——容忍少量误差与幻觉
    ↓ Jev 树形路由（幻觉检测 + 描述规范化）
语言特化层（带语言标签的 DSL 节点）
    ↓ Jev 树形路由（叶子级语法补全）
目标语言代码 / 命令 / DSL 文本
```

**关键变化**：从逻辑描述到公约数 DSL 的转换由通用 Agent 完成，而非 Jev。Jev 的职责从“理解逻辑描述”收缩为“在公约数 DSL 上做路由、验证与规范化”。

### 3.3 责任归属表

| 层 | 生成者 | 验证者 | 容错策略 |
|----|--------|--------|----------|
| 逻辑描述 → 公约数 DSL | 通用 Agent | Jev | 容忍幻觉与偏差，Jev 发现并分流，将问题反馈回通用 Agent |
| 公约数 DSL → 特化层 | Jev | 通用 Agent | 容忍映射分歧，通用 Agent 审等价性和判断歧义分支行动方向 |
| 特化层 → 目标代码 | Jev | 沙箱 / Tier 1 | 结构确定，不容忍语法错误 |

## 4. 核心接口与封闭性

### 4.1 Jev 的 Choice / Score / Noul 定义

**结论**：三者是候选内判断接口，不是生成接口。

**接口规则**：

| 接口 | 输入 | 输出 | 约束 |
|------|------|------|------|
| Choice | 有限候选集 + 上下文 | 候选 ID | 只返回候选 ID，不生成新文本 |
| Score | 候选集 + 上下文 | ranking + 置信度 | 用于排序，不直接决定最终选择 |
| Noul | 门控问题 + 上下文 | `continue / stop / unknown` | 用于是否结束、是否完整等门控 |

**候选来源**：路由引擎、符号表、词表、规范化器。Jev 不构造候选。

**底层建议**：规则引擎 + 小模型 + 约束解码；LLM 仅用于候选分类。

**校准目标**：

- Choice top1 ≥ 98%
- Score top1 ≥ 95%
- Noul ≥ 99%

**示例**：变量位置优先从 `/dynamic/variables` 选 `a`，而不是让 Jev 编造 `a`。

### 4.2 封闭集合与动态路由表边界

**结论**：路由表 schema 任务期间冻结；`/dynamic` 是独立运行期层；动态节点结构封闭，实例动态。

**规则**：

- 路由表结构不可变。
- `/dynamic` 不是目标语言表的静态节点，也不是表扩展，而是独立运行期层。
- 路由引擎在运行期把 `/dynamic` 层合并进候选视图。
- 动态节点必须来自符号表，带 `symbol_name / symbol_type / scope / provenance`。
- Jev 只能选已注册动态节点，不能发明。

**示例**：`a = 10` 后，`/dynamic/variables/a` 挂载；Jev 写变量时 Choice 到该节点，输出 `a`。

### 4.3 词表工厂与任务期间封闭性

**结论**：不违反，因为词表工厂仅任务前生效；任务中不新增、不热补丁。

**规则**：

- 任务前：可预判、可用户请求、可工厂生成候选，Jev 验证，人审批后合并。
- 任务中：`vocabulary_gap` 只抛质疑或记录，不生成当前任务可用词表。
- 可用预定义兜底词表，但兜底词表也必须任务前已存在。
- 任务结束后的缺口记录，作为下一任务前词表工厂输入。
- 不直接修改当前任务使用的词表版本。

**示例**：遇到 `hash_sha256` 缺词，当前任务抛 `vocabulary_gap`；记录后下一任务前生成 `shell_crypto_v1`。

### 4.4 双向校验的对称性

整个系统形成**双向校验闭环**：

| 方向 | 生成者 | 验证者 | 验证内容 |
|------|--------|--------|----------|
| 代码生成 | JevAgent | 通用 Agent | 语义正确性 |
| 词表生成 | 通用 Agent | JevAgent | 语法正确性 |
| 公约数 DSL 生成 | 通用 Agent | JevAgent | 节点存在性、描述规范化、幻觉分流 |
| 特化映射生成 | JevAgent | 通用 Agent | 语义等价性 |

- **Jev 生成代码 → 通用 Agent 审**：通用 Agent 语义强，能发现逻辑错误。
- **通用 Agent 生成词表 → Jev 审**：Jev 结构强，能发现语法错误。
- **通用 Agent 写公约数 DSL → Jev 审**：Jev 做节点存在性检查、描述规范化、幻觉分流。
- **Jev 做特化映射 → 通用 Agent 审**：通用 Agent 审语义等价性、歧义分支行动方向。

两者失败模式正交，互相补位。这是异构交叉的第二种形态——不是同一产物的双方审查，而是**各自擅长的产物交给对方验证**。

## 5. 语义分层与映射

### 5.1 核心原则

#### 5.1.1 语义公约数原则

**高层语义节点只包含在多数目标语言中可验证行为等价的概念。**

可进入公约数层的：

- 控制流抽象：顺序、分支、循环、异常。
- 数据操作抽象：声明、赋值、读取、聚合、映射。
- 调用抽象：函数定义、调用、返回。
- 基本类型抽象：整数、浮点、布尔、字符串、列表/数组。

不可进入公约数层的：

- 内存管理语义：手动 malloc/free、所有权、GC。
- 指针与引用语义：指针算术、借用检查、智能指针。
- 并发模型：goroutine、async/await、线程调度。
- 语言特有语法糖：推导式、宏、模板元编程。

**判断标准**：如果一个语义节点在不同语言中的行为等价性无法被独立验证，它就不属于公约数层。目标语言表必须为该节点附加语言特定的前置/后置条件才能保证正确性时，该节点应下沉到特化层。

#### 5.1.2 底层特化原则

**语言特有实现细节只在针对性优化的树形图中处理，由 Jev 在该层做语法补全选择。**

特化层不是“兜底”，而是**一等公民**。C 的指针解引用、Rust 的借用、Python 的 GIL 相关操作，都应在各自语言表中有完整的路由子树，而不是塞进公约数层用条件分支区分。

#### 5.1.3 公约数层是容忍区，不是精确区

**从逻辑描述到公约数 DSL 的转换由通用 Agent 完成，不由 Jev 完成。**

通用 Agent 在这一层允许出现两类不完美：

- **少量幻觉**：可能写出公约数层 schema 中不存在的节点。
- **少量描述偏差**：可能用了非标准 DSL 写法，但逻辑语义正确。

这两类不完美不会阻塞流程，而是由下游的 Jev 路由阶段**发现并分流**：

| 类型 | 特征 | Jev 处理 |
|------|------|----------|
| 真幻觉 | 节点语义无法映射到任何公约数节点 | 抛 `unknown_node` 质疑，阻塞 |
| 描述偏差 | 语义可映射，表面形式非标准 | 静默规范化，不阻塞 |
| 语义歧义 | 可映射到多个公约数节点 | 低置信时抛质疑或走 Score 排序 |

#### 5.1.4 分层粒度受 Jev 能力约束

Jev 不擅长多步推理，每一步准确率会下降。因此从“公约数节点”到“特化层叶子”的语义跳跃不应超过 2-3 层。公约数层的抽象层级不能过高，否则 Jev 在路由时置信度会显著衰减。

主设计稿“块大小 ≤ Jev 上下文窗口的 50%”的约束，在语义分层中同样适用：一个块对应的公约数语义子树，应控制在一屏可读的规模。

### 5.2 公约数层独立路由表

**结论**：有，独立为 `semantic_v1`，共享同一路由引擎。

**规则**：

- 节点定义在 `dsl/semantic/nodes.json`。
- 路由路径如 `/semantic/control/loop/for`。
- 目标语言表通过 `semantic_mappings` 关联。
- 同一引擎，不同表。
- 公约数层只保留跨语言可验证等价节点。

**示例**：`(loop ...)` 在 `semantic_v1` 路由；进入 Python 表后查 `semantic_mappings` 到 `/python/control/for`。

### 5.3 公约数层最小完备集

**结论**：第一批必须覆盖控制、数据、函数、IO、基础类型与 raw。

**集合**：

- 控制：顺序、if、switch、for、while、iterate、try/catch/raise。
- 数据：declare、assign、read/index、write、add/sub/mul/div、cmp、and/or/not。
- 函数：define、call、return。
- IO：input、output。
- 类型：int、float、bool、string、list/array、map。
- 特殊：raw。

**判断标准**：

- 至少两种目标语言有行为等价实现，且黄金样例可验证 → 进公约数层。
- 三种语言中一种不等价 → 下沉特化层。
- 仅一种语言有 → 特化层。
- 未定义行为差异大 → 特化层 + guards。
- 性能差异大但语义等价 → 公约数层 + notes。

**示例**：`(loop ...)` 进公约数层；`(malloc size)` 只进 C 特化层。

### 5.4 与主骨架的对应

主设计稿骨架：

```
/control
  /loop
    /for
    /while
    /iterate
  /branch
    /if
    /switch
/data
  /declare
  /assign
  /read
  /write
/function
  /define
  /call
  /return
/io
  /input
  /output
/error
  /try
  /catch
  /raise
```

公约数语义层与此骨架一一对应，但**不包含**语言特有子分支（如 `/c/pointer`、`/rust/borrow`）。这些特化子树挂在各语言表的 `/dynamic` 或独立特化分支下。

### 5.5 DSL 规范化

**结论**：规则库 + 模式匹配优先，Jev Choice 仅处理歧义候选。

**规则**：

- 候选来自规范化规则、同义 DSL 形式、历史偏差日志。
- 映射成功 → 记录 `description_deviations`，静默继续。
- 多候选 → Score 排序，低置信抛质疑。
- 无法映射 → `unknown_node`，阻塞。
- 错误由通用 Agent / Tier2 发现。
- 同一模式 >20 次或描述偏差率 >5% 触发 DSL 修订。

**示例**：`(for i in range n sum+=arr[i])` 被规范化到 `/control/loop/for`，记录偏差但不阻塞。

### 5.6 特化层映射

**结论**：静态声明优先，Jev 推断仅 fallback。

**规则**：

- 映射表由语言表维护者维护，版本化。
- 查不到映射时，Jev 推断候选来自：同骨架其他语言映射、历史映射、相似节点。
- 推断结果由 Tier2 审。
- 允许 `raw_fallback` 时回退 raw。
- 不允许则 `no_mapping` 质疑。

**示例**：C 表有 `"(deref ptr)" -> "/c/pointer/deref"`；Rust 表查不到时，Jev 推断候选 `*ptr` 或 `ptr.as_ref()`，Tier2 审。

### 5.7 特化节点结构

```json
{
  "node_id": "/c/pointer/deref",
  "parent": "/c/pointer",
  "type": "leaf",
  "template": "*{ptr}",
  "slots": ["ptr"],
  "guards": ["not_null(ptr)", "aligned(ptr, 4)"],
  "maps_from": ["(deref ptr)"],
  "notes": "指针算术场景需走 /c/pointer/arith 分支",
  "raw_fallback": true
}
```

关键字段：

- `maps_from`：声明该特化节点可从哪些公约数节点映射而来，供 Jev 路由时匹配。
- `guards`：语言特定的前置条件，不满足时 Jev 应抛出质疑或回退 `raw`。
- `raw_fallback`：是否允许回退到原始代码块。

### 5.8 特化层路由

Jev 在特化层的路由流程：

```
公约数节点 (deref ptr)
  ↓
目标语言表选择（已确定 C 表）
  ↓
在 C 表 /c/pointer 分支下 Choice
  ↓
候选：/c/pointer/deref、/c/pointer/arith、/c/pointer/null-check
  ↓
Jev 根据上下文（ptr 来源、是否可空、是否参与算术）选择
  ↓
到达叶子，填充模板
  ↓
若 guards 不满足 → 抛 missing_condition 或 unknown_symbol
```

### 5.9 多语言共享的公约数节点

同一公约数节点可被多张语言表映射：

| 公约数节点 | Python 映射 | C 映射 | Shell 映射 |
|-----------|------------|--------|-----------|
| `(loop ...)` | `for` / `while` | `for` / `while` | `for` / `while` |
| `(index arr i)` | `arr[i]` | `arr[i]` 或 `*(arr+i)` | `${arr[$i]}` |
| `(add sum x)` | `sum += x` | `sum += x` | `sum=$((sum+x))` |
| `(deref ptr)` | 无映射 → 质疑 | `*ptr` | 无映射 → 质疑 |

### 5.10 映射声明

每张语言表在元数据中声明其支持的特化映射：

```json
{
  "table_id": "c_v1",
  "target_language": "c",
  "skeleton_ref": "common_skeleton_v1",
  "semantic_mappings": {
    "(deref ptr)": "/c/pointer/deref",
    "(index arr i)": "/c/array/index",
    "(add sum x)": "/c/assign/add"
  }
}
```

Jev 在从公约数层进入特化层时，直接读取该映射，减少 Choice 层数。

### 5.11 跨语言等价性验证

**结论**：以黄金样例跨层执行为主，形式化仅关键子集。

**规则**：

- 覆盖正常路径、边界、异常。
- 并发、浮点、指针、内存模型默认不进公约数层，或标 raw/guards。
- 抽样：Tier1 全量确定性检查；黄金样例全量；Tier2 抽样。
- 不等价：修正映射；不可修正则下沉；否则标 raw。
- 结果定位到具体特化节点。

**示例**：`(loop ...)` 分别生成 C/Python 执行，比对结果；不等价则修 C 表 `/c/control/for` 映射。

黄金样例跨表验证扩展为**跨层验证**：

```
公约数 DSL → C 代码 → 编译执行 → 结果
公约数 DSL → Python 代码 → 解释执行 → 结果
比对结果是否等价
```

不等价时，定位到具体特化节点，修正映射或标记 `raw`。

### 5.12 映射失败处理

当 Jev 在特化层找不到映射时：

1. 检查 `raw_fallback` 是否允许。
2. 允许则生成 `raw` 节点，保留原始代码。
3. 不允许则抛 `no_mapping` 质疑，附上公约数节点和当前语言表 ID。
4. 通用 Agent 尝试从其他语言表推断或请求 DSL 澄清。
5. 无法补全则升级人类仲裁。

### 5.13 不可提取部分与 raw 节点

主设计稿第 13.3 节的 `raw` 节点机制继续保留。当公约数层无法表达某个底层操作时，保留原始代码块：

```
raw:
  source_lang: C
  code: |
    char *p = (char *)&x;
    p[0] ^= 0xFF;
  reason: pointer_arithmetic
```

`raw` 节点是特化层的安全阀，不参与公约数层的等价性验证。

**raw 节点控制**：

- raw 占比 >10% 触发词表工厂/特化映射。
- >30% 阻塞新任务。
- 跨语言转换时 raw 保留原始代码。
- raw 不参与等价性验证，整体正确性靠人工和沙箱。
- 统计 raw 占比作为信号。

## 6. JevAgent 设计

### 6.1 职责边界

**做**：

- 在给定块内走树形路由。
- 从有限分支中选择下一个节点。
- 在公约数层做节点存在性检查、描述规范化、幻觉分流。
- 在特化层做映射选择、语法补全选择。
- 从动态符号表中选择已定义变量/函数/模块。
- 填充叶子模板槽位。
- 验证候选词表的语法正确性。
- 逻辑不清时抛出结构化质疑。

**不做**：

- 跨块逻辑推理。
- 全局状态维护。
- 自由文本生成。
- 长上下文理解。
- 主动发明词表项（只做验证，不做创造）。
- 生成公约数 DSL（由通用 Agent 写）。

### 6.2 处理流程

```
输入：块描述（自然语言 / 已写好的公约数 DSL）+ 符号环境 + 目标语言表 ID + 词表
  ↓
1. 表选择（单表直接使用，多表走 Jev Choice）
  ↓
2. 词表验证（若本轮有新增候选词表）
  ↓
3. 公约数层路由：
   - 节点存在性检查
   - 描述规范化
   - 幻觉与偏差分流
  ↓
4. 特化层路由：
   - 优先查 semantic_mappings
   - 查不到再走 Jev Choice
   - 每层：Jev Choice / Score / Noul
  ↓
5. 遇到需要变量/函数名：
   - 优先从动态符号表 Choice
   - 符号表无匹配时抛质疑
   - 兜底词表仅作为最后手段
  ↓
6. 到达叶子：模板填充
  ↓
7. 输出块代码 + 路由路径 + 置信度 + 词表验证结果 + dsl_normalization
  ↓
8. 低置信 / 逻辑缺口 → 抛结构化质疑
```

### 6.3 输出格式

```json
{
  "block_id": "blk_003",
  "path": ["/shell", "/file", "/archive", "/tar-gz"],
  "confidence": 0.94,
  "code": "tar -czf {out} {src}",
  "slots": {
    "out": {"source": "symbol_table", "value": "backup.tar.gz"},
    "src": {"source": "symbol_table", "value": "./data"}
  },
  "ambiguities": [],
  "symbols_used": ["backup.tar.gz", "./data"],
  "symbols_defined": [],
  "vocab_validation": {
    "candidate_vocab_id": "shell_crypto_v1",
    "valid": true,
    "issues": []
  },
  "dsl_normalization": {
    "input_nodes": 5,
    "normalized_nodes": 5,
    "unknown_nodes": [],
    "description_deviations": [
      {"input": "(for i in range n sum+=arr[i])", "normalized_to": "/control/loop/for"}
    ]
  }
}
```

## 7. 树形路由表设计

### 7.1 表的元结构

```json
{
  "schema_version": "1.0",
  "table_id": "python_v3",
  "target_language": "python",
  "skeleton_ref": "common_skeleton_v1",
  "root": {
    "type": "branch",
    "choices": ["control", "data", "function", "io", "error"]
  },
  "nodes": {
    "/control": { ... },
    "/control/loop": { ... },
    "/control/loop/for": {
      "type": "leaf",
      "template": "for {var} in {iterable}:",
      "slots": ["var", "iterable"],
      "dynamic": true
    }
  }
}
```

### 7.2 节点类型

| 类型 | 作用 | Jev 调用 |
|------|------|----------|
| `branch` | 分支节点，有多个子节点 | Choice |
| `leaf` | 叶子节点，带模板 | 无（直接填充） |
| `score_node` | 多候选排序 | Score |
| `gate` | 门控（是否继续/结束） | Noul |
| `dynamic` | 动态符号挂载点 | Choice（从符号表） |
| `symlink` | 跨表链接 | 无 |

### 7.3 骨架规范

所有语言表共享同一套抽象骨架：

```
/control
  /loop
    /for
    /while
    /iterate
  /branch
    /if
    /switch
/data
  /declare
  /assign
  /read
  /write
/function
  /define
  /call
  /return
/io
  /input
  /output
/error
  /try
  /catch
  /raise
```

语言特有语法只能出现在叶子或可选子分支，**不能修改骨架层级**。

### 7.4 多表选择

**结论**：关键词 + 嵌入粗筛，Jev 精判。

**规则**：

- 表数量 <10：Jev 直接 Choice。
- ≥10：关键词/嵌入粗筛 → Jev 精判。
- 低置信才并行试 top-2。
- 并行成本由编排层承担。
- 缓存失效按版本向量。
- 选择结果缓存：同会话相似任务复用。

## 8. 动态符号表

### 8.1 问题

Jev 在需要写变量名、函数名、模块名时，如果没有动态符号表，只能：

- 使用兜底词表编造名字 → 与实际代码不一致。
- 抛质疑 → 增加人工负担。

### 8.2 方案

通用 Agent 在代码生成过程中**实时维护符号表**，并**动态挂载到路由表的 `dynamic` 节点**。

### 8.3 符号表结构

```json
{
  "scope_id": "func_main",
  "parent_scope": "module_top",
  "symbols": {
    "variables": [
      {"name": "a", "type": "int", "defined_at": "blk_001", "scope": "func_main"},
      {"name": "user_list", "type": "list", "defined_at": "blk_002"}
    ],
    "functions": [
      {"name": "process_data", "params": ["x", "y"], "defined_at": "blk_005"}
    ],
    "modules": [
      {"name": "os", "imported_at": "blk_000"},
      {"name": "json", "imported_at": "blk_000"}
    ],
    "classes": [
      {"name": "Config", "defined_at": "blk_007"}
    ]
  }
}
```

### 8.4 动态挂载机制

当通用 Agent 检测到符号定义时：

```
1. 捕获定义事件（变量赋值、def、class、import）
   ↓
2. 生成对应节点，挂载到目标表的 /dynamic 分支
   ↓
3. 节点属性：
   - type: dynamic
   - symbol_name: "a"
   - symbol_type: "variable"
   - scope: "func_main"
   - display: "a (int)"
   ↓
4. Jev 下次路由到变量位置时，直接 Choice 到该节点
```

### 8.5 作用域管理

- 符号表按作用域分层，与代码作用域对应。
- Jev 路由时，只看到**当前可见作用域**的符号。
- 作用域退出时，对应动态节点自动卸载。
- 跨作用域引用时，通用 Agent 负责补全限定名。

### 8.6 优先级

Jev 在需要符号时，按以下优先级 Choice：

```
1. 当前作用域动态符号（最高）
2. 父作用域动态符号
3. 全局动态符号
4. 预定义词表
5. 抛质疑（"未找到匹配的变量，是否新建？"）
```

### 8.7 动态节点示例

Python 中定义了 `a = 10` 后，`/dynamic/variables` 下出现：

```json
{
  "/dynamic/variables/a": {
    "type": "dynamic",
    "symbol_name": "a",
    "symbol_type": "int",
    "scope": "func_main",
    "template": "a"
  }
}
```

接下来 Jev 想写变量时，直接选中 `/dynamic/variables/a`，输出 `a`，**不再走兜底词表**。

### 8.8 回滚与一致性

**结论**：按确认点保存版本向量，块内变更暂存，确认点提交。

**规则**：

- 版本向量包含：代码 commit、DSL commit、符号表快照、动态节点集合、块间契约、词表/路由表/骨架版本、缓存键。
- 回滚到最近确认点，卸载该点之后动态节点。
- 恢复符号表快照。
- 跨块引用以确认点版本为准。
- 不可逆副作用已执行则记录补偿或人工处理。

**示例**：`blk_003` 审查失败，回滚到 `blk_002` 确认点，`blk_003` 新增变量与动态节点全部卸载。

### 8.9 分层中的角色

动态符号表在分层架构中承担**跨层符号传递**：

- 公约数层符号：`i`、`sum`、`arr`，类型为抽象类型（整数、列表）。
- 特化层符号：C 中 `int i`、`int *ptr`；Python 中 `i: int`、`arr: list`。
- 动态挂载时，符号节点同时挂载到公约数层和特化层，Jev 在各层 Choice 时看到对应粒度的符号。

### 8.10 粒度

**结论**：变量级、函数签名、类型级；不挂表达式级。

**规则**：

- 变量、函数、类、模块、别名都表示。
- 遮蔽、闭包、导入别名由作用域管理。
- 函数签名含参数与返回类型。
- 表达式级不挂载，避免爆炸。

## 9. 词表 / 模板表 / 对话表

### 9.1 词表

- **封闭集合**，任务前可扩展，任务期间不可新增。
- 结构：

```json
{
  "word_id": "encrypt",
  "canonical": "加密",
  "synonyms": ["encrypt", "cipher", "加密"],
  "category": "operation",
  "related_nodes": ["/shell/crypto/encrypt"]
}
```

- **覆盖率指标**：每次任务后统计词表外意图数。

### 9.2 模板表

- 定义叶子节点的代码形态与槽位。
- 槽位填充来源：动态符号表 / 块内上下文 / 质疑补全。
- **封闭集合**，任务前可扩展。

### 9.3 对话表

- 把结构化缺口翻译成人话。
- 承担：追问、报错、确认、软拒绝。
- **封闭集合**，任务前可扩展。

### 9.4 词表工厂

**问题**：任务前扩展词表通常靠人工。当任务领域陌生（如从未处理过的 crypto 操作），人工写词表慢且易错。

**方案**：通用 Agent 作为**词表编写者**，Jev 作为**词表语法验证者**。两者分工明确，互相校验。

#### 9.4.1 触发条件

- 运行时缺口检测触发 `vocabulary_gap`。
- 任务开始前通用 Agent 预判需要新词表。
- 用户显式请求扩展某领域词表。
- 上一任务缺口记录。
- raw 占比 >10% 触发词表工厂/特化映射。

#### 9.4.2 流水线

```
1. 需求：识别词表缺口（领域、意图、涉及节点）
   ↓
2. 生成：通用 Agent 生成候选词表（JSON）
   - 词条结构、命名规则、同义词、类别
   - 关联的路由节点
   - 与现有词表的继承/覆盖关系
   - 语义层标签
   ↓
3. 验证：Jev 检查候选词表语法正确性
   - 词条结构是否符合 schema
   - 命名是否一致（大小写、分隔符、前缀）
   - 同义词是否与现有词表冲突
   - 关联节点是否在路由表中存在
   - 类别是否在允许集合内
   - semantic_layer 是否合法、maps_from 是否指向存在的公约数节点
   ↓
4. 冲突检查：与现有词表比对
   - 重名 / 同义词碰撞
   - 类别冲突
   - 节点重复挂载
   ↓
5. 回归测试：跑黄金样例
   - 现有样例不回归
   - 新词条能被正确路由
   ↓
6. 版本发布：合并到词表
   - 记录 diff、来源、验证结果
   - 版本号递增
```

#### 9.4.3 Jev 的验证职责

Jev 只做**判断**，不生成词条。它的验证项：

| 验证项 | Jev 调用类型 |
|--------|-------------|
| 词条结构是否符合 schema | Noul |
| 命名是否一致 | Score |
| 同义词是否与现有冲突 | Noul |
| 关联节点是否存在 | Noul |
| 类别是否在允许集合 | Choice |
| 词条语义是否与节点匹配 | Score |
| semantic_layer 是否合法 | Noul |
| maps_from 是否指向存在的公约数节点 | Noul |

验证结果结构化输出：

```json
{
  "candidate_vocab_id": "shell_crypto_v1",
  "valid": false,
  "issues": [
    {
      "type": "synonym_collision",
      "word_id": "encrypt",
      "conflict_with": "common_v2/encrypt",
      "severity": "high"
    },
    {
      "type": "unknown_node",
      "word_id": "hash_sha256",
      "related_node": "/shell/crypto/hash-sha256",
      "reason": "节点不存在于 shell_v2"
    }
  ],
  "suggestions": [
    "将 encrypt 重命名为 encrypt_file 避免冲突",
    "先在 shell_v2 中新增 /shell/crypto/hash-sha256 节点"
  ]
}
```

#### 9.4.4 词表版本化

- 每次扩展生成新版本号。
- 保留完整变更历史。
- 支持回滚到任意版本。
- 词表版本与路由表版本绑定（`vocab_ref`）。

#### 9.4.5 继承与覆盖

- 词表支持继承：`base_vocab` + `overrides`。
- 通用词表作为基础，领域词表增量扩展。
- 冲突时显式声明覆盖，不静默替换。

#### 9.4.6 语义层标签扩展

词表工厂增加**语义层标签**：

```json
{
  "word_id": "deref",
  "canonical": "解引用",
  "synonyms": ["deref", "解引用", "取指针内容"],
  "category": "operation",
  "semantic_layer": "language_specific",
  "related_nodes": ["/c/pointer/deref", "/rust/pointer/deref"],
  "maps_from": ["(deref ptr)"]
}
```

Jev 验证候选词表时，增加验证项：`semantic_layer` 是否合法、`maps_from` 是否指向存在的公约数节点。

#### 9.4.7 审批

**结论**：审版本摘要、diff、Jev 验证报告、回归结果。

**规则**：

- 低风险自动合并，高风险人工。
- 审批粒度：版本。
- 验证失败：拒绝合并；可部分合并；严重人工介入。
- 不审批自动合并仅限低风险、小 diff、回归通过。

#### 9.4.8 词表语法与词条语义的仲裁分工

- 词条结构、命名、同义词冲突、节点存在性 → Jev。
- 词条语义是否与节点匹配 → 通用 Agent。
- Jev Score 可做语义匹配特征，但最终语义仲裁倾向通用 Agent。
- 优先级：安全 > 结构语法 > 语义 > 风格性能。

**示例**：`encrypt` 同义词碰撞 → Jev；`encrypt` 是否真对应加密操作 → 通用 Agent。

## 10. 质疑机制

### 10.1 触发条件

| 条件 | 质疑类型 |
|------|----------|
| 必填槽位缺失 | `missing_slot` |
| 循环终止条件不清 | `missing_condition` |
| 逻辑分支不完整 | `incomplete_branch` |
| 符号表无匹配 | `unknown_symbol` |
| 词表覆盖不足 | `vocabulary_gap` |
| 全局扫描后无节点可表达 | `no_mapping` |
| 候选词表验证失败 | `vocab_invalid` |
| 公约数节点不存在 | `unknown_node` |
| guards 不满足 | `guard_failed` |

### 10.2 质疑格式

```json
{
  "ambiguity_type": "missing_condition",
  "context_path": "/control/loop/while",
  "block_id": "blk_004",
  "description": "循环终止条件未指定",
  "candidates": [
    "遍历完所有元素",
    "满足某条件时退出",
    "外部信号控制"
  ],
  "impact": "影响循环次数和终止行为",
  "blocking": true,
  "suggested_default": null
}
```

### 10.3 处理流程

```
Jev 抛质疑
  ↓
通用 Agent 尝试补全：
  - 从全局状态推断 → 补全
  - 从接口契约推断 → 补全
  - 从历史块推断 → 补全
  - 从词表工厂生成新词条 → 补全
  ↓ 无法补全
升级人类仲裁（结构化呈现，一键决策）
  ↓
决策回写 → 规则沉淀 → 未来同类不重复问
```

### 10.4 自动补全质疑边界

**结论**：通用 Agent 可补全，但必须生成候选 + 证据 + 置信，交 Jev 验证。

**规则**：

- 低置信、不可逆、跨块副作用 → 升级。
- 补全错误由 Tier1/Tier2 发现。
- 不可逆操作必须阻塞。
- 补全失败回滚最近确认点。
- 自动补全与人类仲裁切换条件：低置信 / 不可逆 / 跨块 / 安全敏感。

**示例**：循环终止条件缺失，通用 Agent 从契约推断 `i < n`，Jev 验证后使用；若不可逆则阻塞。

### 10.5 质疑去重与批量

- 同一缺口一次会话只提一次。
- 任务期间只记录，任务结束统一汇总。
- 按频率和影响面排序。

## 11. 与通用 Agent 的集成

### 11.1 分工

| 层 | 职责 |
|----|------|
| 通用 Agent | 逻辑分解、块序列编排、全局状态、符号表、接口契约、风格统一、质疑处理、**词表工厂**、**编写公约数 DSL** |
| JevAgent | 公约数层节点存在性检查与规范化、特化层路由、符号选择、模板填充、块内质疑、**词表语法验证** |

### 11.2 块切分标准

- 一个块 = 一个可独立验证的逻辑单元。
- 块大小 ≤ Jev 上下文窗口的 50%。
- Jev 上下文窗口建议 8k–16k token。
- 块对应一个可测试行为。
- 块间接口显式声明。
- 一个块对应的公约数语义子树应可独立验证跨语言等价性。
- 块切分半自动：通用 Agent 初切，人类可调。

### 11.3 块间接口契约

```json
{
  "block_id": "blk_003",
  "semantic_layer": ["/control/loop/for", "/data/assign", "/data/read"],
  "requires": {
    "variables": ["a", "user_list"],
    "functions": ["process_data"],
    "modules": ["os"]
  },
  "provides": {
    "variables": ["result"],
    "functions": []
  },
  "side_effects": ["write_file:output.txt"],
  "preconditions": ["a > 0"],
  "postconditions": ["result != None"]
}
```

- 通用 Agent 生成 `requires / provides / side_effects / preconditions / postconditions`。
- Jev 验证符号和路径。
- Tier1 验证 pre/post。
- 不一致回滚最近确认点。
- `semantic_layer` 与 DSL 通过版本向量绑定。

### 11.4 调用协议

通用 Agent 传给 JevAgent 的不再是“块描述（自然语言）”，而是**已经写好的公约数 DSL 片段 + 符号环境 + 目标语言表 ID**。

```
通用 Agent → JevAgent：
{
  "block_id": "blk_003",
  "semantic_dsl": "(loop (init (var i 0)) (cond (< i n)) (step (inc i)) (body ...))",
  "target_table": "python_v3",
  "symbol_env": { ... },
  "style_constraints": { ... },
  "context_window_budget": 2048,
  "candidate_vocab": null
}
```

```
JevAgent → 通用 Agent：
{
  "block_id": "blk_003",
  "code": "...",
  "path": [...],
  "confidence": 0.94,
  "ambiguities": [...],
  "symbols_used": [...],
  "symbols_defined": [...],
  "vocab_validation": null,
  "dsl_normalization": {
    "input_nodes": 5,
    "normalized_nodes": 5,
    "unknown_nodes": [],
    "description_deviations": [
      {"input": "(for i in range n sum+=arr[i])", "normalized_to": "/control/loop/for"}
    ]
  }
}
```

## 12. 异构交叉检查

### 12.1 原理

- JevAgent：窄而深，结构精确，错法可枚举。
- 通用 Agent：宽而浅，语义强，错法不可枚举。
- 两者失败模式正交 → 分歧信号价值高。

**结论**：必须不同类型/不同能力模型；Jev 判断特化，通用 Agent 语义理解。

**规则**：

- Jev：判断特化模型，不输出规范外词，无幻觉率，但缺长规划。
- 通用 Agent：语义理解模型，长规划强，但天然有幻觉。
- 两者失败模式天然互补。
- Tier2 审查者不能是生成者同一实例。
- 若只有同源模型，退化为同构自审，不能宣称失败模式正交。
- 同构自审必须加确定性检查、规则库、人工抽样。

### 12.2 双向校验

| 方向 | 生成者 | 验证者 | 验证内容 |
|------|--------|--------|----------|
| 代码生成 | JevAgent | 通用 Agent | 语义正确性 |
| 词表生成 | 通用 Agent | JevAgent | 语法正确性 |
| 公约数 DSL 生成 | 通用 Agent | JevAgent | 节点存在性、描述规范化、幻觉分流 |
| 特化映射生成 | JevAgent | 通用 Agent | 语义等价性 |

### 12.3 检查粒度

- **段级**（不是词级）：一个完整逻辑块审一次。
- **分阶段**：
  - 语义审：原始输入 + 逻辑 DSL。
  - 映射审：逻辑 DSL + 生成代码。
  - 路径审：路由路径 + 表结构。
  - 等价性审：公约数层到特化层的映射是否保持行为等价，`raw` 节点是否被正确标记。

### 12.4 分歧归因

| 类型 | 特征 | 处理 |
|------|------|------|
| 逻辑歧义 | 输入模糊 | 澄清 DSL |
| 表缺陷 | Jev 受表限制选错 | 修正表 |
| 审查幻觉 | 通用 Agent 过度推理 | 降噪 |
| 词表语法错 | Jev 验证发现 | 修正词表 |
| 语义层错位 | 公约数节点与特化节点映射不等价 | 修正映射或下沉节点 |
| DSL 描述偏差 | 通用 Agent 写的 DSL 非标准但语义正确 | Jev 静默规范化，不阻塞 |
| 不可归因 | 双方都有道理 | 升级人类 |

### 12.5 仲裁规则

- 结构类分歧 → 倾向 JevAgent。
- 语义类分歧 → 倾向通用 Agent。
- 代码类分歧 → 看沙箱和测试。
- 词表类分歧 → 看 Jev 验证结果。
- 词表语法/结构类 → Jev。
- 词条语义匹配类 → 通用 Agent。
- 不可归因 → 人类仲裁。
- 优先级：安全 > 结构语法 > 语义 > 风格性能。

## 13. 审查分层与确认点

### 13.1 分层策略

| Tier | 内容 | 成本 | 触发 |
|------|------|------|------|
| Tier 0 | Jev 置信度 | 零 | 高置信 + 可逆 → 直接过 |
| Tier 1 | 确定性检查 | 零 LLM | 永远开 |
| Tier 2 | 通用 Agent 审查 | 中 | 中低置信 / 不可逆 / 跨语言 |
| Tier 3 | 人类仲裁 | 高 | Tier 2 分歧 |

### 13.2 阻塞规则

- **可逆操作**（生成代码、写 DSL）→ 非阻塞，异步审查。
- **不可逆操作**（执行 shell、写文件、网络请求、数据库修改）→ 阻塞，审查通过才落地。

### 13.3 可逆 / 不可逆判定

**结论**：按执行动作判定，不按生成物。

**规则**：

- 生成代码/DSL/命令文本：可逆，非阻塞。
- 实际写文件：不可逆/半不可逆，阻塞。
- 实际执行 shell：不可逆，阻塞。
- 网络请求代码：可逆。
- 实际网络请求：不可逆，阻塞。
- 数据库修改：不可逆，阻塞。
- 边界模糊默认阻塞。
- 由编排层策略引擎判定。

**示例**：生成 `tar -czf` 命令可逆；实际执行 `tar` 阻塞审查。

### 13.4 确认点队列

```
Jev 生成块 → 入队
  ↓
Tier 1 检查通过 → 标记确认点
  ↓
Tier 2 异步审查
  ↓
审查通过 → 确认点升级
审查分歧 → 回滚到最近确认点
```

### 13.5 确认点回滚范围

**结论**：回滚确认点版本向量覆盖的全部状态。

**规则**：

- 回滚：代码、DSL、符号表快照、动态节点、块间契约、缓存键、审查状态。
- 不回滚：已发布词表/路由表版本，只切换引用。
- 不可逆副作用已执行，记录补偿。
- 所有状态通过确认点版本向量绑定。
- 多状态一致性以确认点为准。

**示例**：回滚到 `blk_002`，`blk_003` 生成的代码、DSL、符号、动态节点、契约一起回退。

### 13.6 抽样策略

**结论**：每 100 块或每日校准。

**规则**：

- 高置信抽样，中低全审。
- 校准不准时提高抽样率。
- 错误率反馈周期 1 天/100 块。
- 避免滞后：在线校准 + 滑动窗口。
- 高置信段：按比例抽样。
- 中置信段：全审。
- 低置信段：全审 + 加严。
- 不可逆段：全审 + 阻塞。
- 抽样比例根据历史错误率动态调整。

## 14. 沙箱与安全

### 14.1 白名单机制

- 允许的命令、参数模式、路径前缀、网络目标。
- 变量替换先冻结或限制在受控集合。
- AST 级解析，不只看字符串。
- 安全团队定义，AST + 白名单 + 沙箱三层。

### 14.2 危险领域检测

- 不是黑名单（`rm -rf`、`curl | sh`）。
- 是能力白名单（能做什么，不能做什么）。
- 命令替换、`eval`、编码、环境变量、`bash -c`、`find -exec`、`xargs` 全部纳入检查。

### 14.3 执行前检查链

```
Jev 输出 → AST 解析 → 白名单检查 → 沙箱试运行 → 正式执行
```

- AST 解析每种目标语言实现。
- 变量替换不确定时拒绝执行或沙箱试运行。
- Shell 组合空间大，白名单 + AST + 沙箱三层覆盖。
- 危险能力白名单，不是黑名单。

**示例**：`rm -rf` 不在能力白名单，直接拒绝。

## 15. 逻辑 DSL 层

### 15.1 定位

- 语言无关的高层逻辑表示。
- 可读、可编辑、可 diff、可回写。
- 类似反汇编器的“逻辑汇编”。
- 在跨语言分层架构中，DSL 分为公约数语义层与语言特化层。

### 15.2 格式

**结论**：双格式，S-表达式 canonical，缩进语法 sugar。

**规则**：

- 机器处理 S-表达式。
- 人类编辑缩进语法。
- 工具链支持 diff、编辑、回写。
- 两者可互相转换。
- round-trip 测试保证等价。

**缩进语法示例**：

```
loop:
  init: i = 0
  cond: i < n
  step: i += 1
  body:
    if arr[i] > threshold:
      sum += arr[i]
```

**S-表达式示例**：

```
(loop
  (init (var i 0))
  (cond (< i n))
  (step (inc i))
  (body
    (if (> (index arr i) threshold)
      (add sum (index arr i)))))
```

### 15.3 不可提取部分

```
raw:
  source_lang: C
  code: |
    char *p = (char *)&x;
    p[0] ^= 0xFF;
  reason: pointer_arithmetic
```

### 15.4 Round-trip 要求

```
C → DSL → C    （等价）
DSL → Python → DSL  （等价）
```

### 15.5 Jev 在公约数层的三项职责

Jev 不生成公约数 DSL，它做三件事：

**第一，节点存在性检查。** 通用 Agent 写的每个公约数节点，Jev 检查是否存在于公约数层的 schema 中。不存在 → 抛 `unknown_node` 质疑，附上节点名和上下文。

**第二，描述规范化。** 通用 Agent 可能写了 `(loop-for i 0 n (add sum arr[i]))` 或 `(for i in range n sum+=arr[i])` 这类非标准但逻辑等价的写法。Jev 在路由时将其映射到规范化的公约数节点（如 `/control/loop/for`），表面形式差异被吸收，不阻塞流程。

**第三，幻觉与偏差的分流。** 不是所有不完美都值得阻塞。真幻觉阻塞，描述偏差静默规范化，语义歧义走 Score 排序或低置信质疑。

### 15.6 DSL 规范化验证

当 Jev 在公约数层发现通用 Agent 写的 DSL 存在描述偏差时：

1. 尝试映射到规范化公约数节点。
2. 映射成功 → 记录 `description_deviations`，静默继续。
3. 映射到多个候选 → 走 Score 排序，低置信抛质疑。
4. 无法映射 → 抛 `unknown_node` 质疑，阻塞。
5. 规范化记录汇入分歧日志，作为 DSL 语法优化的信号源。

## 16. 跨语言转换

### 16.1 流程

```
源语言代码
  ↓ 源语言表识别侧（LLM 容错解析）
逻辑 DSL / 公约数语义层
  ↓ 目标语言表生成侧
目标语言代码
```

在分层架构下：

```
源语言代码
  ↓ 源语言表识别侧
公约数语义层 semantic_v1
  ↓ 目标语言表 semantic_mappings
语言特化层
  ↓ Jev 特化层路由
目标语言代码
```

### 16.2 提取规则

- 识别“本质逻辑”：遍历、条件、聚合、调用。
- 忽略“实现选择”：`i++` vs `++i`、索引 vs 迭代器。
- 不可提取 → `raw` 节点保留。

### 16.3 语义差异处理

- 骨架层只保留行为等价节点。
- 语义有差异的放叶子 `notes` 或 `guards`。
- 转换时提示用户。
- **结论**：notes/guards 由语言表维护者写，Jev schema 验证，通用 Agent 语义审。
- 性能差异大 → notes 提示。
- 未定义行为不同 → guards 约束。
- guards 不足 → raw。
- notes/guards 随表版本化。
- 跨语言转换时提示用户。

### 16.4 跨表一致性

- 骨架规范版本化，所有表引用。
- 加表时跑骨架一致性检查。
- 黄金样例跨表验证。
- 公约数层与主骨架漂移时，骨架版本化；一致性检查扩展至语义层。

## 17. 人类仲裁

### 17.1 原则

- 人类只处理分歧，不处理流程。
- 工作量 O(分歧数)，非 O(任务量)。
- 分歧率随系统成熟持续下降。

### 17.2 分歧排序

| 影响 \ 歧义 | 高 | 低 |
|-------------|-----|-----|
| 高 | 优先 + 详细展示 | 快速确认 |
| 低 | 批量处理 / 默认 | 自动解决 |

### 17.3 呈现方式

- 只展示分歧点，不展示完整路径。
- 并排对比：Jev 选什么 / 通用 Agent 选什么 / 各自理由。
- 最小上下文。
- 一键决策：A / B / 都不对 / 需要更多信息。
- 结论：并排 A/B，一键决策，规则回写各表。
- 高影响/低歧义默认 + 快速确认。

### 17.4 决策回写

- 同类分歧自动消解。
- 表优化信号。
- DSL 澄清信号。
- 词表优化信号。
- 规则沉淀。
- 规则回写各表，人工审批。

### 17.5 规则沉淀

**结论**：沉淀到各表，分散动态进化，不建集中规则库。

**规则**：

- 分歧归因到表缺陷：路由表、词表、模板表、对话表、映射表、审查表。
- 每次分歧是消除表构建缺陷的机会。
- 修补对应表，版本化。
- 回归测试防止过拟合。
- 高频/高影响分歧才沉淀；保留例外。
- 后续同类歧义应减少。

**示例**：同类循环歧义出现三次，补 `/control/loop/while` 的 guards/notes，而不是写通用规则。

## 18. 版本绑定、缓存、成本与统计

### 18.1 版本绑定与缓存失效

**结论**：统一 manifest 绑定所有版本。

**规则**：

- manifest 包含：skeleton、semantic、table、vocab、mapping、symbol_snapshot、code_commit、dsl_commit。
- 缓存键包含 manifest。
- 跨会话缓存按版本向量失效。
- 相似任务判定基于 manifest + 意图指纹。

**示例**：词表升到 `common_v3`，旧缓存自动失效。

### 18.2 成本模型

**结论**：分阶段成立，总成本需低于直接人工。

**规则**：

- 可逆操作异步审查，延迟秒级。
- 不可逆操作阻塞，延迟人工。
- 初期人类仲裁工作量高，后期下降。
- 若总成本高于人工，降级 Tier2/Tier3。
- 可接受延迟按操作类型分级。

### 18.3 通用 Agent 幻觉率统计

**结论**：按三类指标统计，超过阈值降级。

**规则**：

- unknown_node <2%。
- 描述偏差 <5%。
- 语义歧义 <10%。
- 超过则：更小候选集、更多 Jev 验证、人工抽样。
- 统计频率：每任务/每日。

## 22. 核心设计原则

1. **封闭集合**：词表、模板表、对话表任务期间不可变，保证可验证性。
2. **动态符号**：代码中新增的定义实时挂载到路由表，避免兜底编造。
3. **双向校验**：Jev 生成代码 → 通用 Agent 审语义；通用 Agent 生成词表 → Jev 审语法；通用 Agent 写公约数 DSL → Jev 验证与规范化；Jev 做特化映射 → 通用 Agent 审语义等价。
4. **结构约束幻觉**：Jev 只做选择，不做生成，错误空间可枚举。
5. **异构交叉**：窄而深 + 宽而浅，失败模式正交，分歧信号价值高。异构要求不同类型模型；同源则退化为同构自审。
6. **人类仲裁最小化**：只处理分歧点，工作量随系统成熟下降。
7. **可逆非阻塞，不可逆阻塞**：审查策略按可逆性分，不按风险分；可逆按执行动作判定。
8. **IR 即提取物**：逻辑 DSL 是从代码中提取的高层逻辑，不是路径。
9. **块内自治，块间契约**：Jev 只管块内，通用 Agent 管块间。
10. **骨架共享，叶子分化**：跨语言转换靠共享骨架，落地靠各表叶子。
11. **分歧驱动改进**：分歧日志是表优化、DSL 澄清、词表优化的信号源。
12. **词表可工厂化**：通用 Agent 写，Jev 验，人审批；仅任务前生效。
13. **公约数分层**：高层语义只保留跨语言可验证等价的抽象节点，语言特有细节下沉特化层。
14. **容忍区设计**：公约数层允许通用 Agent 的少量幻觉与描述偏差，由 Jev 在下游发现并分流。
15. **职责对齐能力**：通用 Agent 写 DSL（语义强），Jev 验证与规范化（结构强），失败模式正交。
16. **幻觉分流**：真幻觉阻塞，描述偏差静默规范化，语义歧义走 Score 或质疑。
17. **特化层是一等公民**：语言特有语法不是兜底，而是完整可测试的独立子树。
18. **映射优先于推断**：能查表就不走 Jev Choice，减少置信度衰减。
19. **规范化日志即信号**：描述偏差的累积是 DSL 语法优化的直接输入。
20. **raw 节点是安全阀**：不可提取部分显式标记，不参与等价性验证。
21. **跨层验证**：黄金样例从跨表验证升级为跨层验证，覆盖公约数层到特化层的完整链路。
22. **Jev 只做判断**：在公约数层做节点存在性检查和规范化，在特化层做语法补全选择，不生成 DSL。
23. **规则沉淀分散在各表**：不建集中规则库，修补对应表并版本化。
24. **版本向量统一绑定**：代码、DSL、符号表、动态节点、契约、表版本、缓存键通过确认点版本向量绑定。
25. **路由表 schema 冻结**：任务期间不可变；`/dynamic` 独立运行期层；结构封闭、实例动态。

## 23. 已冻结结论与后续优化项

### 23.1 已冻结结论

- DSL 格式：双格式，S-表达式 canonical，缩进语法 sugar。
- 动态符号表粒度：变量级、函数签名、类型级；不挂表达式级。
- 块切分自动化程度：半自动，通用 Agent 初切，人类可调。
- 多表选择粗筛机制：关键词 + 嵌入粗筛，Jev 精判。
- 跨语言语义差异标注：notes/guards 由语言表维护者写，Jev schema 验证，通用 Agent 语义审。
- 人类仲裁界面：并排 A/B，一键决策，只展示分歧点。
- 词表工厂触发：任务前预判、用户请求、上一任务缺口记录；仅任务前生效，半自动生成 + Jev 验证 + 人审批。
- 词表验证失败回退：拒绝合并；可部分合并；严重人工介入；当前任务不热补丁，使用已有兜底词表或抛质疑。
- 公约数层：独立 `semantic_v1`，共享路由引擎，只保留跨语言可验证等价节点。
- 特化映射：静态声明优先，Jev 推断仅 fallback。
- 异构交叉：必须不同类型/不同能力模型；同源退化为同构自审。
- 仲裁优先级：安全 > 结构语法 > 语义 > 风格性能。
- 自动补全边界：通用 Agent 可补全，但必须候选 + 证据 + 置信，交 Jev 验证；低置信、不可逆、跨块、安全敏感升级。
- 规则沉淀：分散到各表，不建集中规则库。
- 沙箱白名单：安全团队定义，AST + 白名单 + 沙箱三层。
- 成本模型：可逆异步，不可逆阻塞；总成本需低于直接人工。
- 版本绑定：统一 manifest 绑定 skeleton、semantic、table、vocab、mapping、symbol_snapshot、code_commit、dsl_commit。
- 抽样策略：每 100 块或每日校准，在线校准 + 滑动窗口。
- raw 节点控制：>10% 触发词表工厂/特化映射，>30% 阻塞新任务。
- 通用 Agent 幻觉率阈值：unknown_node <2%，描述偏差 <5%，语义歧义 <10%。

### 23.2 后续优化项（不阻塞落地）

- 形式化等价性验证覆盖关键子集的程度。
- 特化层 `guards` 的验证责任归属在具体语言表中的细化。
- DSL 规范化器的容忍阈值与 DSL 语法修订触发线的动态调整。
- 通用 Agent 审查 prompt 模板的具体设计。
- 分歧归因的自动化程度提升。
- 词表工厂自动合并的低风险阈值调优。
- 多语言共享公约数节点时的版本同步机制优化。
- `raw` 节点跨语言转换策略的进一步细化。
